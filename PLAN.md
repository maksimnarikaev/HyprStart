# HyprStart — замена меню «Пуск» в стиле Hyprland

План работ. Согласованная концепция: по тапу Win выезжает оверлей из 4 плавающих панелей
с жёсткими гэпами, острыми углами, 1px-рамками и моношрифтом. Обои рабочего стола видны
сквозь панели (живой фон, без скриншотов и блюра).

### 0.2 Аудит DWM-размытия (замеры скриншотами, не «на глаз»)

Проверял так: скриншот экрана до и после показа оверлея + попиксельный анализ.

| Конфигурация | Гэп (обои #270F16) | Панель | Вывод |
|---|---|---|---|
| `AllowsTransparency=true` (layered) + accent | #270F16 | #181C38 | акрил игнорируется |
| `AllowsTransparency=false` + accent + region | #060505 | #141938 | стекло накрыло **весь** экран |
| + `DwmExtendFrameIntoClientArea(-1)` | #060505 | #141938 | блюр работает, но тоже на весь экран |
| тонировка подложки 0x40 вместо 0xB0 | #060505 | #141938 | **тонировка не влияет**: материал DWM почти непрозрачно тёмный |

Выводы:
1. Акрил в DWM физически не режется `SetWindowRgn` — материал накрывает весь прямоугольник
   окна. «Плавающие панели с чистыми гэпами» и реальный блюр несовместимы без отдельного
   окна на каждую панель.
2. На этой системе `ACCENT_ENABLE_BLURBEHIND` даёт почти чёрную подложку независимо от
   `GradientColor` — обои под ней гаснут (31% от исходной яркости при alpha 0xB0, ~0% при 0x40).
3. Поэтому по умолчанию `acrylicBackdrop=false`: панели — собственное тёмное стекло
   `#B00B0E17` + рифлёная фактура, гэпы — настоящие обои. Замеры подтверждают: гэп
   `#270F16 → #271530`, панель `#181C38`, на углах читается свечение рамки.

Акрил оставлен как опция: `"acrylicBackdrop": true` (+ `acrylicMode`, `acrylicTint`,
`acrylicBackdropTint`). Включать, если нужен «полноэкранный матовый веер» вместо
плавающих панелей.

### 0.1 Постмортем: баг «залипшей» клавиатуры (найден и исправлен)

**Симптомы у пользователя:** перестали печататься буквы и не работал Backspace,
вместо ввода открывались разные приложения (проводник, поиск, параметры).

**Причина:** хук подавлял **keyup** клавиши Win, но пропускал keydown. Windows оставалась
в состоянии «Win зажат», поэтому каждая следующая клавиша трактовалась как `Win+<клавиша>`:
`E` → проводник, `S` → поиск, `I` → параметры, буквы и Backspace — «не работают».
Состояние создал сам автотест: он дважды эмулировал тап Win с подавлением keyup.

**Исправление:**
- открытие меню переведено на `RegisterHotKey` — API вообще не вмешивается в поток клавиатуры,
  десинка модификаторов не бывает по построению;
- `interceptWindowsKey` по умолчанию `false`, режим помечен в коде как опасный;
- миграция настроек `v1 → v2`: у старых конфигов перехват принудительно выключается;
- `--selftest` переписан на Alt+Space и теперь **проверяет отсутствие** активного хука;
- в баг-репорте по миграции: дефолт `Version` в модели был равен текущей версии, поэтому
  старый файл без поля `version` миграцию не запускал. Теперь дефолт `0`.

**Аварийное восстановление ввода** (если такое повторится с любым приложением):
нажать физическую Win дважды, либо перезапустить `explorer.exe` через Ctrl+Shift+Esc.

**Бэклог:** корректная замена нативного «Пуск» возможна только через схему с инъекциями
(подавлять keydown Win и довставлять его через `SendInput` при нажатии второй клавиши),
это отдельная задача с собственными тестами. До неё режим хука включать нельзя.

Замеры из последнего прогона (1920×1080, dpi=1, таскбар в автоскрытии):
```
layout: apps=12,12 512x1020 | pinned=534,12 1374x632
        frequent=534,654 756x378 | quick=1300,654 608x378
        polybar=12,1042 1896x26      <- 1080-12-26, место таскбара занято оверлеем
```

## 1. Решения (зафиксированы)

| # | Вопрос | Решение |
|---|--------|---------|
| D1 | Стек | C# + **WPF (XAML)**, net8.0-windows, один процесс. Без WebView2 |
| D2 | Прозрачность | true per-pixel alpha (`AllowsTransparency`), заливка `rgba(15,15,25,0.85)`. Acrylic (`SetWindowCompositionAttribute`) — опция в настройках, по умолчанию **выключен** (в референсе блюра нет) |
| D3 | Хук Win | **ОТМЕНЕНО, см. 0.1.** Открытие меню — `RegisterHotKey` (`Alt+Space`, `WM_HOTKEY`). `WH_KEYBOARD_LL` остался в коде как легаси за флагом `interceptWindowsKey=false` |
| D4 | Жизненный цикл | Резидентный процесс в трее, окно pre-warmed (Show→Hide на старте), кэш индекса и иконок на диске |
| D5 | Стиль | radius = 0, рамки 1–2px, гэпы 10px, Cascadia Mono, палитра тёмно-фиолетовая + красно-розовый акцент |
| D6 | Данные закреплённого | собственный `pins.json` (+ drag-reorder, «закрепить» из списка). Родной `start2.bin` не трогаем |
| D7 | «Частые» | собственный счётчик запусков `usage.json` (не `UserAssist`) |

### Почему не WebView2
- 3–4 процесса `msedgewebview2.exe`, +150–200 МБ RSS, не мгновенный старт.
- Для сквозной прозрачности нужен composition-controller (`CreateCoreWebView2CompositionControllerAsync`
  + DirectComposition), а не просто `DefaultBackgroundColor` — это +1 день работы и лишний источник багов.
- Текст: WPF даёт ClearType, WebView2 — обычный grayscale AA. Для «острого» вайба референса
  резкие моноширинные буквы важнее, чем удобство CSS.

Если всё же хочется HTML/CSS — оценка растёт на ~1 день (см. раздел «Альтернатива»).

## 3. Архитектура

Один процесс `HyprStart.exe`:

```
[Поток 1: UI]        WPF Application, MainWindow (4 панели + polybar), Tray
[Поток 2: HOOK]      выделенный поток, голый Win32 message loop, WH_KEYBOARD_LL
[Поток 3: WORKER]    индексация приложений, извлечение иконок, запись кэша
```

### 3.1 Перехват Win (главный риск)

Автомат состояний в колбэке, без аллокаций, без lock, без try/catch в горячем пути:

- `WM_KEYDOWN` VK_LWIN/VK_RWIN → `winDown = true`, пропускаем дальше (иначе сломаются Win+E/D/L)
- любой другой keydown при `winDown` → `comboUsed = true`
- `WM_KEYUP` Win:
  - `comboUsed == false` → **съедаем событие** (`return 1`) и показываем оверлей → нативный Пуск не открывается
  - `comboUsed == true` → пропускаем, работает штатное сочетание
- сброс флагов по отпусканию всех клавиш; `Win` + мышь = тоже `comboUsed`

Устойчивость:
- колбэк ничего не аллоцирует → нет пауз GC в горячем пути (workstation GC, `SustainedLowLatency` при резиденции)
- поток хука с `THREAD_PRIORITY_TIME_CRITICAL`, отдельный от WPF
- сторожевой таймер раз в 60 с переустанавливает хук (ОС молча снимает хук при таймауте)
- опционально в настройках: поднять `HKCU\Control Panel\Desktop\LowLevelHooksTimeout`
- режим `--diag`: консоль печатает каждое событие хука и решение автомата — так проверяем,
  что Win+Space, Win+Shift+S, Win+R, Win+Tab не пострадали
- аварийный выход: `Ctrl+Alt+Shift+Q` снимает хук, если что-то залипло

Fallback, если хук в конкретной игре/античите не работает: настраиваемое сочетание (по умолчанию `Alt+Space`).

### 3.2 Резидентность и мгновенное открытие

- Windows Run-ключ (`HKCU\...\Run`) → автозапуск с `--tray`, либо Task Scheduler (без UAC)
- single instance через `Mutex`; повторный запуск = «показать»
- на старте: создать окно, показать offscreen, скрыть → визуальное дерево прогрето,
  первый реальный `Show()` укладывается в кадр
- цель: **открытие ≤ 50 мс** после прогрева, cold start ≤ 400 мс, RSS ≤ 120 МБ, idle CPU ≤ 0.3%

### 3.3 Кэш и данные

`%LOCALAPPDATA%\HyprStart\`
```
apps.index.json     # name, target (path | AUMID), kind (lnk|uwp|folder), iconFile, mtime
icons\<hash>.png    # 256 / 48 / 32 px
pins.json           # закреплённые папки и приложения, порядок, размеры плиток
usage.json          # счётчики запусков + последний запуск
settings.json       # раскладка, акцент, acrylic on/off, хоткей, polybar on/off
logs\startup.log    # ротация
```
- Источник списка: скан `%APPDATA%` и `%ProgramData%\...\Start Menu\Programs` (сейчас 65 + 122 `.lnk`)
  + `shell:AppsFolder` (сейчас 248 записей, включая UWP)
- Иконки: `IShellItemImageFactory::GetImage` (корректно и для UWP, размер до 256px), fallback `SHGetFileInfo`
  + `SHIL_JUMBO`; результат — PNG в кэш. Нет иконки → плейсхолдер: первая буква в рамке
- Запуск: `.lnk`/exe → `Process.Start(UseShellExecute=true)`; UWP → `IApplicationActivationManager::ActivateApplication`
  (даёт PID, значит можно честно считать «частые»)
- Инвалидация: по `mtime` папок меню + хэшу пути; полный рескан в фоне при логине и по `F5`
- Первый прогрев после установки ~1–3 с в фоне; дальше кэш читается за миллисекунды

## 4. Визуальная спецификация

Палитра (обновлено в фазе 2 по правкам заказчика — «рифлёное стекло»):
```
panel      rgba(11,14,23,0.77)   #C40B0E17
border     #6E8BFF (лавандовый, 1.5px, из settings.json → panelBorderColor/panelBorderThickness)
glow       та же кисть: две внешние линии 1px с opacity 0.10 / 0.26 (без шейдеров и Effect)
texture    DrawingBrush, TileMode=Tile, Viewport 5x5 Absolute, линии #0AFFFFFF по диагонали
divider    #33FFFFFF, 1px только под шапкой
text       #E8E6E8
text-muted #8B8B9A
accent     #5CE1E6 (холодный ледяной)
```
Скруглений нет вообще (`CornerRadius` не используется). Красные угловые метки и бейджи в углах
панелей удалены. Шапки панелей — прозрачный фон + разделитель 1px снизу.
Гэпы между панелями 15px (в `settings.json` → `layout.gap`, диапазон 14–16).
Типографика: `Cascadia Mono` — контент 12.5px, заголовки секций 10px UPPERCASE + letter-spacing 1.2,
polybar 11px, подсказки 10px. Никаких скруглений: `CornerRadius=0` везде, включая ховер-подсветку.

Хром панели: `Border 1px border` + заголовок секции в левом верхнем углу (`ПРИЛОЖЕНИЯ`, `ЗАКРЕПЛЕНО`,
`ЧАСТОЕ`, `БЫСТРЫЙ ДОСТУП`) + тонкий разделитель под заголовком, у активного элемента — 1px accent.
Ховер: заливка accent с alpha 8–10 %. Никаких теней и градиентов — только плоскости и линии.

### Раскладка (по умолчанию для 1920×1080, всё в settings.json в процентах/px)

**Важно:** сетка считается по `Screen.Bounds` (полный размер экрана), а НЕ по `WorkingArea` —
системный таскбар переведён в автоскрытие, поэтому место под ним тоже наше. Иначе снизу
останется пустая дыра высотой с таскбар.

```
margin 12px, gap 10px, polybar 26px снизу
┌───────────────────────────┬──────────────────────────────────────┐
│ (б) ПРИЛОЖЕНИЯ            │ (а) ЗАКРЕПЛЕНО            ~62% высоты│
│     поиск + A-Z список    │     сетка плиток, папки → раскрытие   │
│     ~520px ширины         ├───────────────────┬──────────────────┤
│                           │ (в) ЧАСТОЕ  ~55%  │ (г) БЫСТРЫЙ ДОСТУП│
└───────────────────────────┴───────────────────┴──────────────────┘
┌ polybar: RAM · CPU · VOL · ▶ трек · часы · подсказки клавиш ─────┐
```
polybar (г): RAM/CPU через `GlobalMemoryStatusEx` + `PerformanceCounter`, громкость через
`IAudioEndpointVolume`, «сейчас играет» через GSMTC (`Windows.Media.Control`) если доступен
иначе блок скрывается. Сплошная линия сверху, моноширинные значения с фиксированной шириной
полей, чтобы цифры не дёргались.

Детали из референса, которые воспроизводим: чипы-статусы вида `[playing]`, метка `master`,
`Vol: 100%` c индикатором `[-----]`, ASCII-разделители, курсор-блок, строка подсказок внизу.

### Управление
- Win (тап) — открыть/закрыть, Esc — закрыть, клик мимо — закрыть
- ↑/↓/Tab — навигация, Enter/Space — запуск, → — войти в папку закреплённого, Backspace — назад
- набор текста — фильтр, `Ctrl+P` — закрепить, `Del` — убрать из «частого», `F5` — рескан
- правый клик по плитке — контекст: закрепить/открепить, открыть расположение, запуск от админа

## 5. Этапы

**Фаза 0 — окружение (15 мин).** SDK 8 per-user, `dotnet new wpf`, сборка, критерий: пустое окно запускается.

**Фаза 3 — секции (день 3).**
Закреплённые (сетка, папки, drag-reorder), частые (счётчик + сортировка + Del), быстрый доступ

*Приёмка:* закрепление/открепление сохраняется между перезапусками, частые адекватно реагируют
на запуски, кнопки быстрого доступа делают ровно то, что подписано, polybar обновляется без лагов.

**Фаза 4 — полировка и приёмка (день 4).**
Анимации появления 80–120 мс (сдвиг+фейд, без скруглений), настройки раскладки, тема, acrylic-опция,
тесты, чек-лист совместимости, `README.md` с инструкцией и откатом.

Итого: **~4 рабочих дня**, MVP (фазы 0–2) — к концу второго.

| Риск | Влияние | Митигация |
|------|---------|-----------|
| ОС снимает хук при таймауте | нативный Пуск вернётся | колбэк без аллокаций, отдельный поток, сторожевой пере-хук, `--diag` |
| `AllowsTransparency` = software rendering | рывки анимации на слабом GPU | анимируем только маленькие элементы, статику кэшируем; при проблемах — acrylic-режим |
| Античит/игра забирает клавиатуру | оверлей не откроется | fallback-сочетание, документируем |
| UWP-иконки приходят мелкими | мыло в плитке | `IShellItemImageFactory` + плейсхолдер с буквой |
| Anti-virus на глобальный хук клавиатуры | ложное срабатывание | локальная подпись не нужна, хук в user-mode, при жалобах — исключение вручную |
| Windows Update ломает недокументированный acrylic | косметика | acrylic опционален, дефолт — flat alpha |

**Откат:** убрать автозапуск (`HKCU\...\Run`) — и родной Пуск возвращается. Ни один системный
файл не патчится, ничего в `Program Files` не ставится, реестр правится только в `HKCU` (опционально
`LowLevelHooksTimeout`, тоже `HKCU`).

## 9. Альтернатива, если нужен именно HTML/CSS

Тот же план, но `HyprStart.App` = WinForms-хост + WebView2 (composition controller для прозрачности)
+ `ui/` на HTML/CSS/JS, связь через `postMessage`/`AddHostObjectToScript`.
Цена: +1 день к фазе 1 и +150 МБ RSS. Плюс: правки внешнего вида без пересборки.
